Focus: when temporary links end and how removal works

This guide explains retention timing, expiry expectations and removal requests. For the first upload path see Free Image Hosting. For embed formats see Share Image Link.

When the retention clock starts

Choose 1 day, 7 days or 30 days on /upload before you upload. The retention period is intended to start when the upload completes successfully and a hosted URL is created.

What expiry means in practice

  • After the selected period, the hosted file is intended to become unavailable at the original URL.
  • Expiry is not a promise that every browser, CDN or third-party cache copy disappears instantly.
  • If the upload page shows an expiry time for your result, treat that value as the service timing for that upload.

Expiry vs removal request

The public upload page does not provide a self-serve instant delete control for normal temporary uploads. To request removal of an image you control, send the image URL through the contact page or email yuyananuu@gmail.com.

Waiting for expiry and sending a removal request are different actions. A removal request is handled by support; it is not the same as proving every cached copy is gone worldwide.

FAQ

When does the countdown start?

After a successful upload creates the hosted URL for the retention you selected beforehand.

Does expiry clear all caches immediately?

No. The hosted file is intended to stop being available at the URL; third-party or browser caches may lag.

Can I delete a temporary image myself on the page?

There is no public instant-delete control for normal temporary uploads. Request removal with the image URL via contact.

What should I include in a removal request?

The full image URL and enough context to show you control or are reporting the content.

Is permanent storage the same as temporary expiry?

No. Permanent storage needs an approved long-term code and follows different rules on the upload page.
